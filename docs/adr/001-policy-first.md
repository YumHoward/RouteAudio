# ADR-001：以系统策略路由为主路线

- 状态：Accepted
- 日期：2026-11-08
- 决策者：架构组
- 关联：02 §3.1、§13；04 P1

## 背景

Windows 上要做「按进程分配输出设备」，可选路线有四条：系统内部策略 API、进程回环采集重渲染、第三方虚拟声卡、自研内核驱动。

产品目标是「配置一次、长期正确」，且希望零安装依赖、零额外延迟、免管理员权限。实时音频处理能力（混音、增益、多设备同播）是增强项，不是首发的核心价值。

## 决策

以 `Windows.Media.Internal.AudioPolicyConfig`（系统内部 WinRT 类）作为**主路线**：

- 通过 `RoGetActivationFactory` + `IInspectable::GetIids` 探测接口，只在命中白名单 IID 时启用；
- 写入「进程 → 端点」的持久化策略，由音频引擎在会话创建时执行；
- 进程回环作为兜底后端，虚拟声卡作为可选增强，内核驱动延后到 v2 评估。

## 理由

1. **零额外延迟、位精确**：不经过我们的进程，音质与延迟与直连无差异。
2. **无需常驻音频线程**：正常运行时只是一个配置与自动化工具，资源占用极低。
3. **免管理员、免驱动**：安装与使用门槛最低，符合目标用户（普通玩家/办公者）。
4. **已被开源项目长期验证**：EarTrumpet、SoundSwitch 证明可行且稳定。

## 后果

**正面**

- 首发范围可控，10 周可交付。
- 产品定位清晰：路由策略与场景管理，而非实时音频处理器。

**负面 / 需要承担的成本**

- 依赖非公开契约：Windows 更新可能改变 IID 或虚表布局。必须做到「探测失败即降级」，并保留快速发版通道。
- 无法覆盖独占模式应用、部分受保护内容。必须在 UI 中明确说明并提供替代路径。
- 不满足「通道级音量/多设备同播」等需求，需要流式后端补齐（延迟代价）。
- 不能上架 Microsoft Store（使用内部 API）。

## 备选方案与被否原因

| 方案 | 否因 |
| --- | --- |
| 全部走进程回环 | 25–50 ms 延迟成为默认体验；受 DRM/独占限制；CPU 与稳定性成本更高 |
| 全部走虚拟声卡 | 强制用户安装第三方驱动；许可与兼容性风险；概念复杂 |
| 自研驱动 | 首发周期与签名/蓝屏风险不可接受 |

## 复审条件

- P1 在任一目标系统版本上不通过；
- Windows 大版本更新后连续两个版本需要修补；
- 用户调研显示「低延迟/独占模式」是核心诉求（则启动 v2 驱动评估）。
