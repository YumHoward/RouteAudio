## 3. 端到端验证记录

**目标**：不通过 UI 点击，验证「配置文件 → 对账 → 策略写入 → 新会话落到目标设备 → 状态翻转」。

1. 启动测试音进程（`AudioProbe tone`），确认其会话在 Realtek 扬声器。
2. 写入 `%LOCALAPPDATA%\RouteAudio\config.json`：`AudioProbe.exe → 网易虚拟音频设备`，别名「测试虚拟音箱」。
3. 启动 `RouteAudio.exe`。
4. 应用日志：

```
[policy] 接口就绪 IID=ab3d4648-... set=25 get=26
[ui] 初始化
[apply] AudioProbe → 测试虚拟音箱 ok state=AppliedPendingSession sessionOnTarget=False
[reconcile] devices=3 sessions=8 running=4 desired=1 statuses=1
```

5. 结束测试音并重新启动（模拟应用重新建会话）：

```
219812  AudioProbe  Active  100%  扬声器 (网易虚拟音频设备)     ← 新会话直接落到目标设备
[apply] AudioProbe → 测试虚拟音箱 ok state=ActivePolicy sessionOnTarget=True
```

**结论**：A 路线的产品闭环成立；状态机正确区分「已写入、等新会话」与「已生效」。

## 4. 如何构建与运行

```powershell
# 需要 .NET 8 SDK
dotnet build src/RouteAudio.sln -c Debug

# 运行主程序
src\RouteAudio.App\bin\x64\Debug\net8.0-windows\RouteAudio.exe

# 运行单元测试
dotnet test tests\RouteAudio.Core.Tests\RouteAudio.Core.Tests.csproj

# PoC 工具（设备/会话/策略/回环验证）
tools\AudioProbe\bin\Debug\net8.0-windows\AudioProbe.exe devices
tools\AudioProbe\bin\Debug\net8.0-windows\AudioProbe.exe p1
```

- 配置：`%LOCALAPPDATA%\RouteAudio\config.json`（原子写 + `.bak` 备份）
- 日志：`%LOCALAPPDATA%\RouteAudio\logs\app-yyyyMMdd.log`
- 卸载/重置：删除上述目录即可；策略残留可在 Windows「音量合成器」中恢复

## 6. 已知限制

| 限制 | 影响 | 计划 |
| --- | --- | --- |
| 策略只对新会话生效 | 正在播放的应用切路由后需重新出声才搬家 | UI 显示「已设置（下次生效）」；后续可提示「重启该应用」 |
| 独占模式应用 | 策略与采集均无效 | 兼容模式（C）也无效，明确提示 |
| 受保护内容（DRM） | 无法采集 | 明确提示，不做绕过 |
| 设备变化靠轮询 | 拔出设备后最多 2–3 s 才回退 | 接入设备通知后缩短 |
| 只支持同用户进程 | 受保护/系统进程无法路由 | 记录原因码 RA-007 |
| 目标端点静音会让回环校验「看起来失败」 | 排障时容易被误判 | `devices` 已输出端点音量/静音；`p3` 自动选未静音端点并对比电平 |
